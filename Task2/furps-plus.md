# FURPS+ таблица архитектурно-значимых требований

Цифровизация депозитного и кредитного направлений банка Стандарт

MVP - подача заявок на депозиты в интернет-банке и на сайте

**F**  Functionality
**U**  Usability
**R**  Reliability
**P**  Performance
**S**  Supportability
**+**  ограничения (проектные, реализации, интерфейсные, физические).

| ID | Группа | Требование | Комментарий / обоснование |
|----|--------|------------|---------------------------|
| F-1 | На сайте новый клиент видит список депозитов с актуальными ставками и может подать заявку, указав Ф. И. О. и номер телефона | Источник актуальных ставок должен быть единым |
| F-2 | Заявка с сайта передается в систему кол-центра, менеджер кол-центра перезванивает клиенту и может предложить особые условия | Новый клиент не идентифицирован - обработка через кол-центр |
| F-3 | В интернет-банке клиент видит список депозитов с актуальными ставками и персонализированные ставки лично для него | Персональные ставки рассчитываются по текущему процессу в АБС |
| F-4 | В интернет клиент подает заявку на открытие депозита, указав счет и сумму и подтверждение СМС-кодом | требование безопасности операций |
| F-5 | На MVP заявку на депозит обрабатывает менеджер бэк-офиса и подтверждает условия в АБС | MVP пока сохраняет старый процесс, полная автоматизация через на год |
| F-6 | Ведение ставок по депозитам переносится из Excel-файлов в АБС | Устраняет ручной обмен Excel по почте|
| F-7 | Процесс согласования ставки по заявке (включая спецставки) реализуется в АБС | Автоматизация почтового согласования |
| F-8 | На сайте новый клиент видит полные условия кредита | витрина условий должна читать данные конвейера |
| F-9 | Менеджер в отделении продолжает работу с заявкой созданной клиентом на сайте | единый реестр кредитных заявок |
| F-10 | Подача заявки на кредит в интернет-банке (со счетом зачисления) подтверждается СМС-кодом. | как и F-4 |
| F-11 | Клиент информируется по СМС об изменении статуса заявки на кредит. | требование бизнеса |
| U-1 | Интерфейс соответствует принятыми в компании цветам и бренд-элементы | интерфейс должен быть простым |
| U-2 | Заявки минимльна по количеству полей | барьера для новых клиентов |
| R-1 | Сервисы онлайн-каналов работают 24/7 с доступностью 99,9%. | Требование бизнеса отказоустойчивость и резервирование |
| R-2 | При сбое ЦОД сервисы интернет-банк переключение на резервный ЦОД | сейчас все на одной группе серверов в одном ЦОД - единая точка отказа |
| R-3 | Новый функционал не должен допускать прямой работы интернет-банка с API-БД АБС | Интеграция - асинхронная |
| R-4 | Недоступность АБС/СМС-шлюза не приводит к потере заявок | очереди Kafka? с гарантированной доставкой  |
| P-1 | Отклик операций в онлайн-каналах - миллисекунды | "максимально быстрый отклик" |
| P-2 | Загрузка данных при платежах не дольше 1 секунды (исправить текущую итуацию) | кэширование? |
| P-3 | Горизонтальное масштабирование и балансировка нагрузки между серверами | АБС масштабируется только вертикально... |
| S-1 | Ставки по депозитам в едином источнике АБС | нет рассинхронизации ставок |
| S-2 | Новый функционал интернет-банка выделяется в отдельные сервисы (начало перевода на микросервисную архитектуру) | отдельные сервисы можно масштабировать и развивать независимо от ядра подрядчика |
| S-3 | Разрабатывается документация для дальнейшего расширения системы (архитектура, API, регламенты) | требование бизнеса |
| +1 | + | Очереди сообщений - Apache Kafka (выбор банка) | с Kafka работают только новые сервисы |
| +2 | + | Существующий стек: интернет-банк - ASP.NET/MVC4.5/MSSQL/Delphi/Oracle/PL-SQL/JavaSpringBoot/React.js/Python/Flask/PostgreSQL | новые компоненты должны предпочитать стек |
| +3 | + | Весь внешний трафик сайт и интернет-банк защищается HTTPS | с сайта и из интернет-банка передается чувствительная информация |
| +4 | + | Разграничение доступа: сотрудники депозитного и кредитного бэк-офисов не должны иметь доступа к данным друг друга | требование безопасности |
| +5 | + | Открытие продуктов новым клиентам возможно только после личной идентификации в отделении | Законодательное ограничение |
| +6 | + | Два ЦОД (основной и резервный) АБС масштабируется только вертикально | резервирование сервисов |
