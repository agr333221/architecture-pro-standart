# ADR-002. Передача актуальных ставок в кол-центр и партнерский кол-центр

## Статус

Предложено (дополнение к MVP, см. ADR-001 в Task3).

## Контекст

Большинство клиентов банка Стандарт - пожилые люди.
 После запуска маркетинговой кампании ожидается рост звонков в кол-центр
 Клиентам будет проще уточнить условия открытия депозита по телефону,
 чем разбираться в новых онлайн-процессах.

Проблемы:

1. Операторы кол-центра банка сейчас не видят актуальные ставки по депозитам -
  ставки ведутся в Excel и рассылаются по почте
  (до внедрения модуля ставок АБС из ADR-001 - только так).
2. Кол-центр банка может быть перегружен -
  нужно подключить партнерский кол-центр,
  операторы которого тоже должны консультировать по актуальным ставкам
3. Система партнерского кол-центра - внешняя.
  Партнер готов получать ставки только в виде файлов,
  нет интеграции через API-вызовы

Единый источник ставок описан в ADR-001 - модуль ставок в АБС

## Use Cases

Работа со ставками

| NN | Use Case | Актор/ы | Краткое описание |
|---|----------|--------|------------------|
| UC-1 | Консультация кол-центре банка | Оператор кол-центра - Клиент | Оператор видит в системе кол-центра актуальные ставки по депозитным продуктам |
| UC-2 | Консультация в партнерском кол-центре | Оператор партнерского кол-центра - Клиент | Оператор консультирует по ставкам, полученным из банка в файле|
| UC-3 | Публикация изменения ставок | Менеджер бэк-офиса депозитов | После утверждения новых ставок (в модуле ставок АБС) они доставляются в систему кол-центра и в файл для партнера |

## Функциональные требования

1. Отображение актуальных депозитных ставок в системы кол-центра
2. Автоматическая доставка изменений ставок из модуля ставок АБС в систему кол-центра
3. Формирование файла актуальных ставок ежедневно по расписанию /внепланово
4. Размещение файла на сервере банка, партнерский кол-центр самостоятельно забирает файл
5. Журналирование выгрузок/мониторинг/алертинг - факт формирования файла, факт скачивания, алерты при сбоях
6. В файл и в систему кол-центра передаются только публичные ставки (без персональных)

## Нефункциональные требования

- Актуальность ставок - не хуже нескольких минут после утверждения в АБС
- Доступность сервиса - 24/7
- Безопасность - передача файла только по SFTP
- Стек - JavaSpringBoot/PostgreSQL, Kafka как брокер

## Решение

Диаграммы

- `rates-callcenter-c4-context.drawio` - диаграмма контекста
- `rates-callcenter-c4-components.drawio` - диаграмма компонентов интеграционного решения

Суть решения - расширение конвейера ставок из ADR-001 двумя потребителями:

1. **Сервис ставок кол-центра** - микросервис на платформе системы кол-центра
2. **Экспортер файлов ставок** - компонент (Java в составе адаптера АБС:
   по расписанию (ежедневно) и по событию изменения ставок формирует CSV-файл
   и выкладывает его на SFTP-сервер. Кол-центр-партнер забирает файл по SFTP

## Альтернативы

## Недостатки и ограничения решения

- Партнерский кол-центр получает ставки с задержкой до выгрузки
- Новый элемент в инфраструктуре SFTP-сервер который нужно поддерживать
