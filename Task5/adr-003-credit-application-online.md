# ADR-003. Заявка на кредит онлайн (интернет-банк и сайт)

## Статус

Предложено

## Контекст

После MVP депозитов банк цифровизует кредитное направление:
 клиенты подают заявки на кредит в интернет-банке (ИБ),
 решение клиент получает в течение одного дня

Ключевые факты и ограничения (FURPS+):

- Заявки сейчас попадают в Кредитный конвейер из АБС раз в сутки
- Систему скоринга нельзя нагружать в рабочие часы - предодобренные предложения считаются по расписанию ночью
- Новых клиентов нельзя обслуживать без очной идентификации
- Менеджер в отделении продолжает работу с заявкой созданной онлайн
- Нефункциональные требования - те же, что для депозитного направления:
  24/7 / 99,9%, отклик в миллисекунды, без онлайн-нагрузки на АБС, Kafka, TLS, SMS через существующий шлюз

## Use Cases

| NN | Use Case | Актор/ы | Описание |
|---|----------|--------|------------------|
| UC-1 | Витрина кредитов | Клиент | В интернет-банке и на сайте отображается список доступных кредитов |
| UC-2 | Предодобренное предложение | Клиент | В интернет-банке клиент видит предодобренное предложение |
| UC-3 | Заявка на кредит в интернет-банке | Клиент | Клиент указывает данные заявки и подтверждает SMS-кодом |
| UC-4 | Заявка на кредит с сайта | Новый клиент | Клиент оставляет ФИО и телефон, при заполнении паспорта сразу получает решение (по БКИ) |
| UC-5 | Продолжение заявки в отделении | Менеджер офиса | Менеджер берет онлайн-заявку клиента и продолжает работу с ней |
| UC-6 | SMS о статусе | Клиент | При каждом изменении статуса заявки клиент получает SMS |

## Функциональные требования

1. Актуальная витрина кредитных продуктов
2. Отображение предодобренного предложения
3. Подача заявки на кредит с указанием счета зачисления и подтверждением SMS-кодом
4. Подача заявки с сайта: ФИО+телефон, если паспорт - мгровенное решение по данным БКИ
5. Единый реестр заявок - менеджер в отделении продолжает работу с заявкой клиента
6. SMS информивание клиента об изменениях статусов

## Нефункциональные и архитектурно-значимые требования

- Решение по заявке - в течение одного рабочего дня
- Система скоринга не нагружается предрасчетами в рабочие часы
- Доступность онлайн-каналов 24/7 / 99,9%
- Никакой дополнительной онлайн-нагрузки на БД АБС
- Отклик витрин - миллисекунды
- Шифрование TLS, SMS подтверждения
- Стек: ASP.NET/MSSQL),Java/Camunda,Python,Kafka

## Решение

Диаграммы (файлы в этой директории):

- `credit-online-c4-context.drawio` - диаграмма контекста;
- `credit-online-c4-components.drawio` - диаграмма компонентов (сервис кредитных заявок ИБ и новые компоненты Кредитного конвейера).

Суть решения:

1. Сервис кредитных заявок - новый микросервис интернет-банка:
   Отвечает за витрину кредитов, отображение предложений и прием заявок из ИБ
2. Онлайн-заявки идут напрямую в Кредитный конвейер
3. События статусов - через Kafka:
   конвейер публикует изменения статусов заявок,
   сервис кредитных заявок обновляет статус в личном кабинете,
   сервис уведомлений отправляет клиенту SMS через SMS-шлюз.
4. Заявка с сайта нового клиент: ФИО, телефон, паспорт(опция)
   мгновенное предварительное решение
   клиенту уходит SMS

## Альтернативы

1. **Отдельная новая система онлайн-кредитования.** нет - дублирует функции конвейера
2. **Прямые вызовы сервиса ИБ в систему скоринга.** нет -  критичная внутренняя система

## Ограничения решения

- Зачисление кредитных средств выполняется в АБС по суточному обмену
- Решение для нового клиента с сайта - предварительное, финальное - после визита в отделение
- Предложения актуальны на момент ночного расчета
