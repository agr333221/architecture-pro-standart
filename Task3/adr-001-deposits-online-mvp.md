# ADR-001 архитектура открытия депозитов онлайн (MVP)

## Статус

Предложено (на согласовании с командой цифровой трансформации)

## Контекст

Банк Стандарт начинает цифровизацию депозитного направления.
В MVP клиенты должны иметь возможность:

- подавать заявки на открытие депозита в интернет-банке (с просмотром ставок и подтверждением операции СМС-кодом)
- подавать заявки на депозит на сайте (новые клиенты: ФИО+телефон, далее звонок менеджера кол-центра)

Обработку заявок в MVP продолжает
 выполнять бэк-офис по текущему процессу в АБС.

Ключевые ограничения и факты (из FURPS+):

- Ставки по депозитам сейчас ведутся только в Excel и пересылаются по почте,
  их нужно вести централизованно,
  с разграничением доступа между бэк-офисами депозитов и кредитов.
- БД АБС перегружена и прямые обращения из интернет-банка к БД/API в новом процессе недопустимы
- АБС масштабируется только вертикально
- Монолит интернет-банка (ASP.NET MVC 4.5 .NET 4.5) несовместим с Kafka
- доработка ядра завязана на подрядчика, это нужно избежать
- Стратегическая шина сообщений - Apache Kafka
- в команде Java-экспертиза
- Доступность 24/7 / 99,9%, переживание сбоя ЦОД
- горизонтальное масштабирование новых сервисов 
- Весь клиентский трафик шифруется TLS

## Use Cases

| NN | Use Case | Актор/ы | описание |
|---|----------|--------|------------------|
| UC-1 | Просмотр депозитов и ставок в интернет-банке | Клиент | Клиент видит список депозитов с актуальными ставками и персональные ставки лично для него |
| UC-2 | Подача заявки на депозит в интернет-банке | Клиент | Клиент указывает счет и сумму, подтверждает операцию СМС-кодом - заявка регистрируется и передается в АБС |
| UC-3 | Обработка заявки бэк-офисом | Менеджер бэк-офиса депозитов | Менеджер видит заявку в АБС, согласует ставку (включая спецставки через модуль ставок) - клиенту уходит СМС о согласованной ставке |
| UC-4 | Открытие депозита | Менеджер бэк-офиса депозитов, Клиент | После подтверждения условий депозит создается в АБС - клиент получает СМС об открытии - статус заявки в интернет-банке обновляется |
| UC-5 | Заявка на депозит с сайта | Новый клиент, Оператор кол-центра | Новый клиент видит депозиты со ставками на сайте, оставляет ФИО и телефон - заявка попадает в систему кол-центра; менеджер перезванивает, может предложить особые условия и приглашает в отделение для идентификации |
| UC-6 | Ведение ставок | Менеджер бэк-офиса депозитов или отдела кредитования | Ставки ведутся в модуле ставок АБС c разграничением (депозиты/кредиты), ставки автоматически публикуются в онлайн-каналы |

## Функциональные требования

1. Витрина депозитов с актуальными ставками на сайте и в интернет-банке (+персональные ставки)
2. Подача заявки на депозит в интернет-банке (счет, сумма) с подтверждением SMS-кодом
3. Подача заявки на сайте с передачей в кол-центр
4. Обработка заявок (процесс MVP не меняется) менеджером бэк-офиса в АБС 
5. SMS клиенту о согласованной ставке и об открытии депозита
6. Ведение ставок в АБС (модуль ставок) с разграничением доступа депозиты/кредиты

## Нефункциональные требования

- Доступность 24/7, 99,9%; работа при сбое ЦОД
- Запрет прямых онлайн-вызовов АБС из интернет-банка
- Асинхронная интеграция без потери заявок
- Отклик интерфейса - миллисекунды; справочные данные - кэш
- Горизонтальное масштабирование новых сервисов, балансировка между серверами
- Переиспользование стека; Kafka для очередей; без доработки ядра подрядчиком
- TLS для всего клиентского трафика
- Документация

Диаграммы в drawio:

## Недостатки и ограничения решения

- Появляется новая инфраструктура (Kafka-кластер, микросервисы) - требуется настройка мониторинга и сопровождение
- АБС остается узким местом по производительности и единственным источником операций по счетам
- Заявки с сайта обрабатываются вручную кол-центром - ограничение MVP из-за очной идентификации
